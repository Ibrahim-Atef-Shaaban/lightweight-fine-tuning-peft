# Lightweight Fine-Tuning with LoRA

Adapting `distilbert-base-uncased` to 3-class tweet sentiment classification with LoRA,
a parameter-efficient fine-tuning method, and measuring it against the frozen-backbone
baseline.

## Results

| Model | Eval loss | Accuracy |
|---|---|---|
| Frozen backbone, head-only (baseline) | 1.098 | **32.4%** |
| LoRA fine-tuned | 0.660 | **72.0%** |

32.4% is essentially chance on a 3-class problem — freezing the whole backbone leaves
the classification head nothing useful to work with. Adding low-rank adapters to just
the attention projections more than doubles accuracy, while the base weights stay
frozen and the saved artifact is a few hundred KB instead of a full model copy.

## Configuration

| | |
|---|---|
| **PEFT technique** | LoRA — `r=8`, `lora_alpha=32`, `lora_dropout=0.01` |
| **Target modules** | `q_lin`, `v_lin` (attention query and value projections) |
| **Base model** | `distilbert-base-uncased`, 3-label sequence classification head |
| **Dataset** | `mteb/tweet_sentiment_extraction` — 500 train / 500 test, `seed=42` |
| **Labels** | 0 negative, 1 neutral, 2 positive |
| **Training** | 5 epochs, lr 2e-4, weight decay 0.01, batch size 12 (baseline 4) |
| **Evaluation** | Accuracy on the held-out 500-row test split, every epoch |

## How it works

1. **Baseline** — load DistilBERT, freeze every backbone parameter, train only the
   classification head, evaluate.
2. **Adapt** — wrap the same base model with `get_peft_model` and a `LoraConfig`
   targeting the attention projections. Train for 5 epochs.
3. **Save** — `lora_model.save_pretrained()` writes only the adapter weights.
4. **Reload and verify** — load the adapter back with
   `AutoPeftModelForSequenceClassification` and re-evaluate on the same split to
   confirm the saved artifact reproduces the trained performance.

## Getting started

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
jupyter notebook LightweightFineTuning.ipynb
```

Runs on CPU, but slowly — the baseline evaluation alone takes about 7 minutes there.
A GPU brings the whole notebook down to a few minutes.

### Model weights are not in this repository

`.gitignore` excludes `data/`, `*.pt`, `*.pth`, `*.bin`, `*.safetensors` and
`checkpoint-*/`. Trainer checkpoints and the fine-tuned weights run to hundreds of
megabytes and are fully regenerated by running the notebook — there is nothing to
download. Adapters are saved to `/tmp/lora_DBU` by default; change that path if you
want to keep them.

## Repository layout
